# AGENTS.md

Philly Reps — an address-in, representatives-out civic lookup app. Runs as a native
iOS/Android app and in the browser from one codebase.

Full product spec and data sources: `docs/SPEC.md`. Read it before starting any feature.
This file is conventions and boundaries only.

## Commands

- `pnpm dev` — Expo dev server (press `w` for web, `i`/`a` for simulators)
- `pnpm test` — vitest, unit + district-resolution golden tests
- `pnpm test src/lib/districts.test.ts` — single file
- `pnpm typecheck` — `tsc --noEmit`, must be clean
- `pnpm lint` — eslint + prettier check
- `pnpm data:build` — regenerates `assets/data/*` from upstream sources (network, slow) "— created in step 2, does not exist yet"
- `pnpm data:verify` — checks every bundled district file loads and every rep record
  has a `source_url` and `verified_on`

## Layout

- `src/lib/` — pure TypeScript. Geocoding, point-in-polygon resolution, rep lookup.
  No React, no React Native, no `window`, no `fetch` outside `src/lib/net/`.
  This is the layer that gets tested.
- `src/components/` — shared UI. Platform splits use `Foo.native.tsx` / `Foo.web.tsx`.
- `src/app/` — Expo Router routes.
- `assets/districts/` — bundled simplified GeoJSON, one file per district layer.
- `assets/data/` — bundled representative records, generated by `pnpm data:build`.
- `scripts/` — data build scripts. Node, not bundled into the app.
- `docs/SPEC.md` — product spec, data sources, verified upstream URLs.

## Hard rules

- **Never invent a phone number, email, office address, or representative name.** If a
  field is missing from source data, omit it and let the UI render "not listed". A wrong
  phone number in a civic app sends a constituent to a stranger. This is the single most
  important rule in this repo.
- **Every record in `assets/data/` carries `source_url` and `verified_on` (ISO date).**
  No exceptions, including hand-maintained files.
- **Do not invent upstream URLs.** Only endpoints listed in `docs/SPEC.md` are verified.
  To add one, fetch it first, confirm the shape, then record it in SPEC.md with the date.
- **The user's address never leaves the device except to the geocoder.** No analytics, no
  logging, no crash-report breadcrumbs, no third-party SDK sees it. Do not persist it
  without an explicit opt-in toggle.
- **District resolution is offline and local.** Point-in-polygon against bundled GeoJSON.
  Never call a paid API, an LLM, or a scraper at runtime to decide what district someone
  is in.
- **Coordinates are `[lng, lat]` everywhere**, matching GeoJSON. Use the `LngLat` branded
  type in `src/lib/geo/types.ts`. The Census geocoder returns `{x, y}` — convert at the
  boundary, never pass raw API shapes inward.

## Conventions

- TypeScript strict. No `any`; use `unknown` and narrow.
- Validate every external response with a zod schema at the network boundary. Untyped
  `await res.json()` is not acceptable.
- Errors: `Result<T, E>` from `src/lib/result.ts` in `src/lib/`. Throw only in UI handlers.
- Styling comes from the tokens in `src/styles/tokens.ts`. No hardcoded hex values in
  components — if a color is missing, add a token and say why.
- New district layer = new entry in `src/lib/districts/registry.ts`. The UI iterates the
  registry; it does not hardcode layer names.
- Copy: sentence case, active voice, plain nouns. "Find my representatives", not "Submit".

## Boundaries

- Do not add analytics, telemetry, or ad SDKs.
- Do not add a backend server or database — with one exception: a single stateless
  proxy endpoint at `/api/geocode` that forwards requests to the Census geocoder.
  It holds no state, caches nothing, and makes no decisions. No other backend
  endpoint is permitted. This ships as a static web build plus native binaries;
  the only network calls are the geocoder (via the proxy on web, direct on native)
  and basemap tiles.
- Do not edit files in `assets/data/` by hand. Change `scripts/` and re-run `pnpm data:build`.
  The one exception is `data/manual/philly-council.json`, which has no upstream API — edit
  it directly and bump `verified_on`.
- Do not swap the basemap or add a tile provider that needs a key.
- Do not upgrade MapLibre major versions without being asked.

## Done means

`pnpm typecheck`, `pnpm lint`, and `pnpm test` all pass, and the golden address fixtures in
`src/lib/districts/fixtures.json` still resolve to their expected districts. If you changed
anything under `assets/`, `pnpm data:verify` passes too.

Report what you changed and what you could not verify. Do not claim a data source is
current if you did not fetch it.
